# Как выпустить новую версию

1. Правите файлы в `plugins/<скилл>/skills/<скилл>/`.
2. Поднимаете `version` в `plugins/<скилл>/.claude-plugin/plugin.json`. Без этого у тех, кто уже установил скилл, обновление не появится.
3. Записываете изменения в `plugins/<скилл>/CHANGELOG.md` под заголовком `## <версия> — <дата>`.
4. Проверяете манифесты: `claude plugin validate . --strict`
5. Коммит и `git push`.
6. Ставите тег и отправляете его:

   ```
   git tag <скилл>-v<версия>
   git push origin <скилл>-v<версия>
   ```

Релиз собирает и публикует GitHub Actions — workflow `.github/workflows/release.yml`. К каждому релизу прикладываются архивы **всех** скиллов репозитория — `<скилл>.skill` для claude.ai и `<скилл>.zip` для остальных агентов, — поэтому ссылки вида `releases/latest/download/<скилл>.zip` работают, какой бы скилл ни вышел последним. Если версия в `plugin.json` не совпадает с тегом или в CHANGELOG нет раздела этой версии, релиз не выйдет.

Собрать архивы локально, чтобы проверить перед релизом: `scripts/package-skill.sh <скилл>` — результат появится в `dist/`.

Пересобрать и перезалить файлы уже вышедшего релиза: `gh workflow run release.yml -f tag=<скилл>-v<версия>`.

> [!IMPORTANT]
> Создавайте релизы только через тег. Релиз, созданный вручную на сайте или командой `gh release create`, публикуется от имени вашего личного аккаунта.
